# Apparel Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a static `/apparel/` page that pitches Sondalab merchandise as the funding model for its open-source research, listing three categories, with every outbound commerce link controlled by one variable.

**Architecture:** One Astro page plus one plain TypeScript module. The module holds `APPAREL.storeUrl` (`null` until a provider is chosen) and the three categories; the page derives its whole state from that value — waiting state with a `mailto:` call to action while `null`, live links to the storefront once set. No content collection, no cart, no provider SDK: the site is static output on nginx and cannot own checkout.

**Tech Stack:** Astro 7 (static output), TypeScript, `@sondalab/ui-kit` 0.7.2 design system (Tier A, Page substrate), self-hosted variable fonts. No test runner exists in this repo — verification is `astro check`, `npm run audit` (0 R-violations) and assertions against the built HTML in `dist/`.

**Spec:** `docs/specs/2026-08-27-apparel-design.md`

## Global Constraints

- Branch: `feat/apparel`, cut from `main`. Do not merge or rebase onto `feat/blog`.
- Colour: every colour in an authored `<style>` block must resolve to a `--sl-*` design-system token. **No raw hex, no `rgb()`, no named colours.** `npm run audit` fails the build otherwise.
- Accent: `default` only. Do not add an entry to `@sondalab/ui-kit`'s `accent-registry.json` and do not bump the package.
- Site copy, identifiers, comments and commit messages are **English**.
- Category vocabulary is exactly `Tees`, `Caps`, `Pants`.
- No prices, no percentages, no figures about where money goes anywhere on the page.
- Images: no garment shots exist, so each category carries a generated
  placeholder plate in `src/assets/apparel/`, served through `astro:assets`.
  Real photography replaces the files, not the markup.
- Do not modify `src/content.config.ts`, `src/pages/index.astro`, `src/lib/accents.ts`, or `src/styles/site.css`. Page-local styles go in the page's own `<style>` block.
- The site's e-mail address is read from `SITE.email` in `src/lib/site.ts`; never hard-code it.
- `npm run motion-gate` does not exist on `main`. Do not add it to any command.

- [ ] **Step 1: Create the store switch module**

Create `src/lib/apparel.ts`:

```ts
/**
 * Everything about the Apparel section that changes when a storefront provider
 * is finally chosen. The site is static output on nginx: it cannot own a cart
 * or a checkout, so the whole integration seam is one outbound URL.
 */

export interface ApparelCategory {
  id: string;
  label: string;
  note: string;
  /** Provider collection URL. Falls back to the storefront root when absent. */
  href?: string;
}

export const APPAREL: {
  storeUrl: string | null;
  categories: ApparelCategory[];
} = {
  /**
   * Storefront root. `null` renders the page's "in preparation" state with a
   * mailto call to action; setting it turns every category into a live link.
   * This is the only line that has to change when the provider is picked.
   */
  storeUrl: null,

  categories: [
    { id: 'tees', label: 'Tees', note: 'Heavyweight, printed small.' },
    { id: 'caps', label: 'Caps', note: 'Low profile, no logo wall.' },
    { id: 'pants', label: 'Pants', note: 'Workwear cut.' },
  ],
};

/** Where a category row points, or `null` while the store does not exist yet. */
export function categoryHref(c: ApparelCategory): string | null {
  return c.href ?? APPAREL.storeUrl;
}
```
